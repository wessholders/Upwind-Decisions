# Main + jib boat performance

All default races use the provisional 5 m, 470-inspired **main + jib** table supplied for this trainer. It is model data, not measured 470 telemetry. No spinnaker or automatic sail change is modeled.

## Editable data and interpolation

`src/engine/boat-profile.js` stores the table in knots: its first column is TWA, and the remaining columns correspond to `windSpeeds` (6/10/14/18 kt TWS). It also stores the normal speed-response time constants and the high-wind extension tuning. `BOAT_PROFILES` registers profiles by ID; scenario configuration selects `boatProfile`. The default `speedScale: 1` reproduces the supplied values exactly. The existing boat-speed control is relabeled **Polar speed scale**; changing it deliberately scales the entire table. Boat length still controls the displayed hull, mark clearance and wind-feature units, without silently scaling this 5 m boat's polar.

`src/engine/performance.js` is the shared performance boundary for physics, live forecasting and route estimates. TWA is `abs(signedAngle(heading - localWindFromDirection))`, normalized to 0–180°. Port/starboard and compass wraparound are symmetric. Wind strength comes from the local field in every wind mode. Bilinear interpolation in TWA/TWS is continuous, exact at supplied nodes and bounded by the neighboring values; slopes can change at table nodes.

Below 6 kt, each angle row uses a monotone cubic Hermite extension from zero boat speed at zero wind to its 6 kt value, with the ending slope matching the 6–10 kt segment. Above 18 kt, an exponential tail starts at the 18 kt value and matches the 14–18 kt wind slope, then gradually levels off; its default wind scale is 8 kt. Both boundary transitions preserve value and wind derivative. These are provisional extensions, with no abrupt clamp, added speed floor or new measured-data claim.

At 10 kt TWS and default scale, the targets are 4.6 kt at 45°, 5.2 at 60°, 5.9 at 90° and 3.8 at 180°. Polar lookup itself exposes all reference nodes, including 0–35°. Normal propulsion below the configured minimum sailing angle targets zero. Coasting can decay toward zero; the low-angle data does not permit an effective head-to-wind sailing mode. The established automatic steering/no-go rules remain in place.

## Actual speed and tack integration

Before this change there was no separate normal acceleration/deceleration state. The existing engine evaluated a simple pressure-speed response directly. A small `speedKnots` state now separates target from actual speed. Normal speed approaches the current target exponentially, with initial tuning of **3 s accelerating / 2 s decelerating**. These are response time constants, not fixed maneuver durations. The exact exponential endpoint and mean speed for a substep feed the existing midpoint position/time movement integrator. Displayed speed is actual speed, and knots convert to m/s only for movement. Heading controls and turn timing are unchanged. At the start, the boat is already sailing at its initial close-hauled target.

`tack.js` and its state-machine timing, quintic turn, speed-loss envelope and recovery functions are unchanged. Applying instantaneous head-to-wind polar values during the turn would add an unintended stall. During that maneuver, the polar instead supplies a pressure-aware reference at the entry TWA. After the heading change, that reference blends to the **current heading and current local wind** polar through the existing recovery interval. The established maneuver function remains the sole tack-speed penalty; normal exponential response is not layered over it. At the endpoint, actual speed transfers continuously back to normal response. Entry momentum is retained when tacking from an accelerating reach.

In unchanged conditions, a settled 4.6 kt close-hauled entry has the same fractional tack profile, reaching approximately 3.68 kt and recovering by 8 s. A profile scaled to a 5 kt entry reproduces the previous 5→4→5 kt trajectory sample for sample in uniform, traveling and organic wind. A puff/lull still changes the protected reference using actual local TWS. Mid-turn heading can pass through the no-go zone without erasing that momentum. Tack repetition locks, mark approach and finish rules remain shared.

The former pressure exponent is not multiplied into the polar. A programmatic `performanceModel: 'legacy-pressure'` option retains old speed goldens and analytical fixtures; it is not the default for any player or opponent. Old `speedKnots` and `pressureExponent` configuration keys affect that explicit compatibility mode only. The main UI's obsolete pressure-response control and formula are removed.

## Planners and validation

The current-observation computer receives public profile settings, its actual speed/maneuver state and current wind samples. It uses the same target, maneuver and exponential-response functions, with midpoint integration through its frozen map. It receives no future wind access. Hindsight advances the authoritative physics, groups candidates by actual speed as well as maneuver phase, and derives its horizon from profile close-hauled performance. Both planners' VMG/progress estimates use polar targets instead of constant speed; tack explanations use the actual old speed and new settled target. Pruning, frozen-map forecasting and the restricted steering set remain numerical approximations, not proofs of optimality.

`tests/polar.test.js` checks all 60 supplied nodes, interpolation and boundary continuity, FROM-direction symmetry, low/high-wind extensions, luffing, smooth reach/run speed changes, spatial puff/pocket crossings, frame-rate convergence, exact frozen-observation forecast agreement, hindsight replay and unchanged calibrated tack trajectories. The earlier analytical/tack goldens explicitly retain legacy mode; other full race, wind, mark-clearance, worker and control tests exercise the default polar. Browser QA measures actual turn/recovery speeds, verifies no speed jump when bearing away and observes acceleration toward the reaching target before a valid close-mark finish.
