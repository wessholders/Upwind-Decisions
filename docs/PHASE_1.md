# Phase 1 implementation map

Current physics has since been implemented in the following increment; see [Uniform current](CURRENT.md). References below to disabled/deferred current describe the original Phase 1 scope.

The application is native ES modules and static HTML/CSS. `src/main.js` binds the DOM and owns one animation frame and one optimizer worker. `src/race-controller.js` owns the fixed-step player/NPC lifecycle. There is no framework, account system, sound, or existing local preference persistence.

Reuse unchanged: the polar and exponential speed response (`engine/boat-profile.js`, `performance.js`), moving tack and recovery (`tack.js`), finite course crossings and live guides (`course.js`, `finish.js`, `views/finish-guides.js`), observed-wind NPC (`live-computer.js`), optimizer/worker, results, tack explanations, and replay.

All three requested courses already exist. Finish Upwind is fixed at 1,000 m with a 100 m line and four live 200 m pin laylines. Compass baseline is distinct from course coordinates. The boat currently follows local wind at the configured minimum angle (45 degrees by default); ordinary steering has no separate turn inertia. Only tacks have a physical turn transition. Extend the existing heading resolver with a manual wind-relative target; retain the tack model and all speed physics.

Wind generation is seeded and time indexed. Organic water uses `WindField`, `ParticleSystem`, `WaterRenderer` and `RaceWindLayer`. Its ambient direction intentionally stays at zero; regime shifts act within features. Reuse those renderers for a separate lobby scenario/clock. Extend seeded persistent generators with an optional prescribed sign, preserving legacy random sign when absent. Presets edit existing parameters, never create another wind system.

Configuration inventory: course mode/length, boat length/gate boatlengths; wind mode/difficulty/field/favored side; wind bias/frequency/size/background speed/contrast; compass baseline, polar speed scale, minimum angle, tack turn duration; maximum shift/transition duration; seed; traveling propagation/width/persistent angle/entry start. Retain every control, grouped into course geometry, basic wind, and advanced wind/model tuning. Existing internal parameters (performance model/profile, legacy speed/pressure exponent, tack minimum speed/recovery) remain in the configuration and validation defaults.

New modules: scenario metadata/preset adapter, local player preferences, reusable held-key input, isolated lobby water, and application navigation/setup/dialog bindings. The flat engine configuration remains the session boundary. Setup owns a separate draft; Go to Course validates and calls the existing reset once, leaving the race ready until the player explicitly selects Start Race. Restart and Race Again also return to ready. Opponent mode gates the existing NPC lifecycle/rendering without changing its policy. Manual target commands are serialized in the existing command log for replay and hindsight incumbents.

## Implemented boundaries and behavior

`game-shell.js` owns lobby/setup/dialog navigation, a separate setup draft and the launched configuration. It relocates the real legacy settings controls into the new setup steps, avoiding duplicate control values. `scenario-config.js` validates the flat engine configuration and derives bounded seeded parameter variation once on launch. Restart bypasses variation and reuses that exact derived configuration; returning to setup restores the editable draft rather than perturbing it twice. The seed, preset, randomization flag, environment, opponent and inactive current descriptor travel in `scenario.config`. New seed generation is explicit.

`preferences.js` validates and stores a small local preference object. Blocked or corrupt storage falls back to defaults without preventing sailing. Boat color only changes the existing hull/heading marker fill/stroke; the sail/hull shape, polar and performance data remain unchanged. The existing editable minimum-angle parameter remains authoritative; its default is 45 degrees. The boat profile now declares minimum/default and maximum sailing-angle extension points.

`keyboard.js` installs one set of held-key listeners. Real elapsed input is capped at 0.1 s and converted at 15 degrees/second before the controller multiplies time for fixed-step sailing. Touch controls share this conversion and command path. `trainer.steer` derives the starting target from the current manual or mark-approach angle, mirrors physical steering by tack, and calls `applyAction` with a serializable target-angle command. The heading resolver uses the actual local wind. Manual input cancels aiming; close haul and tack return to the configured minimum. Input during the moving tack is ignored, and Space calls the existing tack action. The old engine has no additional ordinary-turn inertia, so none was invented: its existing tack turn, speed response, integration and finish physics remain authoritative.

Solo prevents NPC advancement, rendering and result rows. Race NPC runs the original policy unmodified. A single main RAF drives gameplay; one separately owned, throttled lobby RAF runs only outside gameplay. Pause, hidden tabs, inspection and exit stop gameplay scheduling. Exit terminates the optimizer and invalidates late results; restart resets player, NPC, accumulator and results exactly once. BFCache restoration can reschedule the existing instance. The lobby clock periodically resets its private field to bound history growth and respects reduced motion and visibility.

## Determinism and limits

Wind and command replay are deterministic for the same full configuration/seed and command log, using the existing fixed timestep and query-order-independent field. Persistent presets prescribe a trend sign while preserving legacy random-number consumption for scenarios without that option. Organic ambient wind intentionally stays at zero; persistent trends are expressed inside moving features, and individual features can deviate around the trend. Randomization off disables parameter perturbation, not the seeded wind model's own feature generation. A seed alone does not reproduce a human's real-time steering inputs. Floating-point behavior across different JavaScript runtimes is subject to the engine's existing numerical precision.

The hindsight search retains the player's manual command route as an incumbent. Its existing action search remains hold/tack/mark approach/close haul; a continuous manual-steering search was not added. Its existing limits and non-optimality disclaimer remain intact. No existing system prevented integration. Ordinary steering inertia is absent in the original model, as noted above.

- Real Edge/Chromium checks at 1440×1000 and 390×844: lobby/setup/back/launch/pause/resume/restart/setup/lobby; saved hull color; all four setup cards fit mobile width; pointer steering; blur/visibility cleanup; reduced-motion lobby; exactly one gameplay RAF after restart; actual complete races on all three courses with the existing NPC; real optimizer results and tack-time inspection. No runtime errors.
- Half-second keyboard holds produce a 52.5° target from 45° at **every** 1×/4×/8×/16× setting (7.5° change). Releasing the key stops input. Touch holds use the same rate.
- Explicit-start regression checks verify an unchanged clock, player position and NPC state while ready on every course and after restart/Race Again. Native browser key events verify no page scrolling from Space (including repeats) or all four arrows, including when a course button or link has focus. Form inputs keep native editing and focused buttons/summaries retain Space activation.
- Hindsight is hidden per race by default, including its route, tack markers, result comparison and tack explanations. Show/Hide Hindsight Reference preserves the computed analysis; hidden routes cannot expand the map bounds. Browser checks verify both toggle states and tack inspection on all three courses. Sticky Main Menu and Change Course header actions work without the pause menu; Change Course opens the first setup step with existing values, and mobile navigation remains visible when scrolled. The brand link also returns to the lobby without discarding the setup draft through a page reload.
- Existing wind-lab browser smoke tests still pass, including pause/replay/seed, drag/keyboard probe, display controls, renderer/physics independence and mobile overflow. The unified browser entry point runs those plus the new game-flow suite. Screenshots are in ignored `artifacts.local/game-*.png`.
- `node scripts/check.js` and `node scripts/build.js` validate native modules and static packaging. No runtime dependencies added.

## Deferred work and technical debt

Deferred as requested: current physics, multiplayer, more boats/environments, more NPCs/difficulties, accounts, progress storage, sound. Current controls are disabled and launch rejects an enabled-current descriptor. Future environments and classes are not selectable.

Removed competing pre-race reset handlers and the former Space-to-pause listener. Added plain modules without a framework or backend. The main technical tradeoff is DOM relocation of legacy controls and a scoped CSS override layer: it preserves every setting and existing view while avoiding a full template rewrite, but a later dedicated setup template could simplify maintenance. The original long browser script's simulator-first assertions were replaced with the new game-flow suite; the wind-lab checks remain available in the unified entry point.
